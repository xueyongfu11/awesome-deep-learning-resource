# 动态量化与静态量化有什么区别，分别适合什么场景？

两者的核心区别是激活值的量化参数在什么时候确定。动态量化通常预先量化权重，在推理时根据当前输入动态计算激活值的 `scale`、`zero-point` 等参数；静态量化则使用有代表性的校准数据提前统计激活值范围，推理时直接使用固定的量化参数。

| 对比项 | 动态量化 | 静态量化 |
| --- | --- | --- |
| 权重量化 | 通常提前完成 | 提前完成 |
| 激活值量化参数 | 推理时动态计算 | 校准阶段提前确定 |
| 校准数据 | 通常不需要 | 需要有代表性的校准数据 |
| 部署成本 | 较低，适合快速验证 | 较高，需要校准和精度评估 |
| 运行时开销 | 存在动态计算量化参数的开销 | 量化参数已固定，运行时开销较小 |
| 常见场景 | CPU 上以 Linear、LSTM、Transformer 为主的模型 | CNN、端侧部署或硬件支持完整 INT8 计算的场景 |

以下情况优先考虑动态量化：

1. 没有可靠的校准数据，希望快速压缩和部署模型。
2. 模型主要由全连接层或循环网络组成，并在 CPU 上推理。
3. 更关注模型体积和实施成本，不要求极致的延迟和吞吐量。
4. 输入分布变化较大，希望激活值的量化范围能随输入动态调整。

以下情况优先考虑静态量化：

1. 对延迟、吞吐量或功耗要求严格。
2. 能提供与真实业务输入分布一致的校准数据。
3. 模型输入分布相对稳定，或者模型以卷积网络为主。
4. 目标 CPU、NPU 或其他加速器对全 INT8 算子有良好支持。

实际选择时应先在目标硬件上建立 FP32、FP16 或 BF16 基线，再比较量化后的精度、P95/P99 延迟、吞吐量、模型大小和内存占用。模型体积变小并不保证推理一定更快，实际收益还取决于算子覆盖率、量化与反量化开销以及硬件和推理框架的支持程度。

动态量化和静态量化描述的是量化参数在推理前还是推理时确定；PTQ 和 QAT 描述的是模型在训练后量化，还是在训练中模拟量化误差。这是两个不同的分类维度。一般可以先尝试动态量化或静态 PTQ；如果静态 PTQ 的精度下降明显，再改进校准数据或使用 QAT。

一句话总结：没有可靠校准数据、追求简单部署时优先动态量化；有代表性校准数据、追求目标硬件上的极致推理性能时优先静态量化。
