# EAGLE-1～3：输入输出、训练损失与推测解码流程

本文围绕几个问题介绍 EAGLE：草稿模型输入输出是什么？为什么 token 序列比特征序列错开一个位置？loss 如何计算？固定树和动态树有什么区别？EAGLE-3 如何改进模型和训练？

## 1. 先区分目标模型、草稿模型和整个系统

- **目标模型（target model）**：原本要运行的大语言模型，提供真实隐藏特征、token 概率，并验证候选。
- **草稿模型（draft model）**：轻量模型，利用目标模型特征快速提出多个候选 token。
- **整个 EAGLE 系统**：交替执行草稿生成和目标模型验证，输出经过验证与采样修正的 token。

整个系统的输入仍是 prompt 的 token IDs 和生成参数，输出仍是生成的 token IDs。EAGLE 改变的是生成过程。

普通自回归生成每生成一个 token 都要运行一次目标模型。推测解码先用草稿模型生成候选，再让目标模型一次前向计算验证多个候选，以减少生成同样长度文本所需的目标模型调用次数。

## 2. 统一下标：特征和 token 分别对应什么

设文本 token 为：

$$
x_1,x_2,\ldots,x_t
$$

在 EAGLE-1/2 中，记目标模型处理到位置 $t$ 时、送入 LM head 的高层特征为 $h_t$。它通过 LM head 产生 **下一 token $x_{t+1}$** 的分布：

$$
p(x_{t+1}\mid x_{1:t})=\operatorname{softmax}(\operatorname{LMHead}(h_t))
$$

这里“高层特征”具体指 LM head 前使用的表示；论文中的 second-to-top-layer 表述按输出层的计数方式理解，不应直接理解为任意架构的倒数第二个 Transformer block。

关键对应关系：

| 对象 | 含义 |
|---|---|
| $h_t$ | 已处理上下文 $x_{1:t}$ 的特征 |
| $\operatorname{LMHead}(h_t)$ | 预测 $x_{t+1}$ 的 logits |
| $\hat h_{t+1}$ | 草稿预测的下一位置特征 |
| $\operatorname{LMHead}(\hat h_{t+1})$ | 预测 $x_{t+2}$ 的草稿 logits |

## 3. EAGLE-1/2 的输入和输出

假设目标模型已有真实特征 $h_1,\ldots,h_t$，并已采样出 $x_{t+1}$。草稿模型接收：

$$
(h_1,\ldots,h_t),\qquad (E(x_2),\ldots,E(x_{t+1}))
$$

其中 $E$ 是 token embedding。位置编号、attention mask、KV cache 等也是实现中的辅助输入。

概念上，特征与对应 token embedding 拼接、投影后，经过轻量 Transformer decoder 预测下一位置特征。原始设计的核心是一层 decoder，而不是另一个完整的小型大语言模型。

```text
历史真实特征 + 向前错开一个位置的 token embedding
                         ↓
                    草稿模型
                         ↓
                  预测特征 ĥ_{t+1}
                         ↓ LM head
                  x_{t+2} 的 logits
                         ↓ 采样 / 候选选择
                    候选 token
```

特征张量通常可理解为 `[batch, sequence_length, hidden_size]`，token IDs 为 `[batch, sequence_length]`，完整词表 logits 为 `[batch, sequence_length, vocab_size]`；树状推理时节点组织和具体返回值依实现而异。

### 3.1 为什么 token 要向前错开一个位置？

$h_t$ 可以产生多种可能的 $x_{t+1}$。如果草稿只看到 $h_t$，它不知道这次实际采样选中了哪个 token。

把 $x_{t+1}$ 告诉草稿，相当于告诉它：已有上下文是 $x_{1:t}$，这次又选中了 $x_{t+1}$，请预测处理这个新 token 后的特征。

例如已经有 `我 喜欢`，目标模型采样出 `吃`：

```text
原始 token：  我          喜欢          吃
特征输入：   h₁          h₂
token 输入： 喜欢        吃
预测特征：   ĥ₂          ĥ₃
```

最后一对输入 $h_2+E(\text{吃})$ 预测 $\hat h_3$，再用它预测 `吃` 后的 token。

### 3.2 没有第一个 token embedding，会不会丢上下文？

不会因为这个错位而漏掉第一个 token。第一个 token 的信息已经进入目标模型特征；例如 $h_2$ 是在处理 `我 喜欢` 的上下文后得到的。

两组输入不是两份必须各自完整的文本，而是相互补充：**已有上下文的表示 + 新选中的 token**。这不意味着 hidden state 无损保存原始文本，而是模型已经通过特征和注意力历史利用了该上下文。

## 4. EAGLE-1/2 的训练 loss

训练时，从冻结的目标模型取得真实特征，监督草稿预测。对于输入 $h_t+E(x_{t+1})$，特征监督目标是 $h_{t+1}$。

### 4.1 特征回归损失

$$
L_{\mathrm{feature}}=\operatorname{SmoothL1}(\hat h_{t+1},h_{t+1})
$$

它要求草稿预测的特征接近目标模型真实特征。

### 4.2 token 分布损失

将真实特征和预测特征送入同一个冻结的目标模型 LM head：

$$
p(v)=\operatorname{softmax}(\operatorname{LMHead}(h_{t+1}))_v
$$

$$
q(v)=\operatorname{softmax}(\operatorname{LMHead}(\hat h_{t+1}))_v
$$

计算软标签交叉熵：

$$
L_{\mathrm{token}}=-\sum_{v\in V}p(v)\log q(v)
$$

注意这里监督的是 **$x_{t+2}$ 的概率分布**，不是输入的 $x_{t+1}$。原始代码使用目标模型的完整概率分布作为软标签，并非只使用一个 token 的 one-hot 标签。目标分布固定时，最小化该交叉熵与最小化 $D_{\mathrm{KL}}(p\Vert q)$ 对草稿参数的效果一致。

### 4.3 总损失与 mask

原始官方训练脚本的默认设置为：

$$
L=L_{\mathrm{feature}}+0.1L_{\mathrm{token}}
$$

这是该脚本的配置，不应视为所有实现必须使用的常数。实际在 loss mask 指定的有效位置取平均，排除 padding、无法配对的末尾位置等；是否只监督回答部分取决于数据处理方式。

目标模型和复用的 LM head 保持冻结，优化草稿部分。原始脚本还给输入特征加噪声，以适应推理时不精确的预测特征。

来源：[原始官方训练脚本](https://github.com/SafeAILab/EAGLE/blob/main/eagle/train/main.py)。

## 5. 草稿如何连续猜多个 token

第一步有目标模型真实特征，后续不能每一步再调用目标模型，否则就失去加速意义。因此草稿把自己的输出继续作为输入：

```text
真实 h_t + 已知 x_{t+1}
           ↓ 草稿
预测 ĥ_{t+1} → 猜 x̂_{t+2}
           ↓ 再输入草稿
预测 ĥ_{t+2} → 猜 x̂_{t+3}
           ↓
          ……
```

实际还会保留历史注意力上下文和 KV cache，上图只展示新增位置。

这引入两个问题：预测特征误差会影响后续预测；训练若只使用真实特征，推理输入却包括预测特征，两者分布会不同。单步准确不保证多步递归也准确。

## 6. 候选树是什么

一条链只保留每个位置的一个候选；一棵树允许同一位置保留多个候选，并沿不同分支继续预测。

```text
我喜欢
  ├─ 吃
  │   ├─ 苹果
  │   └─ 香蕉
  ├─ 看
  │   ├─ 电影
  │   └─ 书
  └─ 听
      └─ 音乐
```

树里的 token 都只是候选，不是最终答案。目标模型可以在一次前向中验证多个节点，最终生成的结果沿一条被接受的路径推进；需要时还会产生修正或额外 token。

### 6.1 Tree attention：不同分支不能互相偷看

例如 `苹果` 能看到公共前缀 `我喜欢`、自己的祖先 `吃`，以及按因果注意力规则可见的当前位置；不能看到其他分支的 `看`、`电影`。

通过特定 attention mask，各分支在一次前向中保持各自的因果上下文。计算后还需要保留被接受路径的缓存，并处理其他候选对应的缓存。

### 6.2 EAGLE-1：预定义树结构

提前规定候选节点的位置及父子关系，例如：

```text
第一层保留 3 个候选
第二层每个候选保留 2 个
第三层每个分支再延伸 1 个
```

这只是示意，不是官方固定参数。**固定的是树的形状，不是具体 token**；每个节点填什么 token 仍由草稿预测。

如果草稿非常确信 `吃`，固定树仍可能给 `看`、`听` 分配较多节点，浪费候选预算。

### 6.3 EAGLE-2：基于置信度动态构建树

EAGLE-2 利用草稿概率判断哪些路径更值得扩展，在预算内生成并筛选候选树。路径置信度考虑沿途 token 的条件概率；可理解为概率连乘，或等价的 log 概率求和。

例如：

$$
q(\text{吃}\mid\text{我喜欢})=0.6
$$

$$
q(\text{苹果}\mid\text{我喜欢吃})=0.7
$$

则这条两步路径的草稿概率为 $0.6\times0.7=0.42$。它是候选优先级的信息，不是目标模型保证接受这条路径的概率。

有把握的路径可以扩展得更深，不确定时则可保留更多并列分支。树结构随上下文变化。具体实现通常包含扩展、评分和最终剪枝，并非每轮可以无成本地任意调整树。

### 6.4 EAGLE-3：沿用动态树，改进草稿预测

EAGLE-2 的主要贡献是候选树策略；EAGLE-3 继续采用该动态树机制，主要改变输入特征、训练目标以及多步训练方式。

来源：[EAGLE-2 论文](https://arxiv.org/abs/2406.16858)、[EAGLE-3 论文 §2.2](https://arxiv.org/html/2503.01840v1#S2.SS2)。

## 7. EAGLE-3 的三项配套改进

### 7.1 输入：融合低层、中层、高层特征

从目标模型选取低、中、高层表示，拼接后投影：

$$
g_t=W_{\mathrm{fusion}}[h_t^{\mathrm{low}};h_t^{\mathrm{mid}};h_t^{\mathrm{high}}]+b
$$

若各特征是 $d$ 维，则拼接为 $3d$ 维，再投影到 $d$ 维。具体选哪些层取决于模型及配置。

融合特征继续与向前错开一个位置的 token embedding 结合，经过投影和轻量 decoder：

```text
低层特征 + 中层特征 + 高层特征
                  ↓ 拼接、投影
                g_t
                  + token embedding E(x_{t+1})
                  ↓ 拼接、投影、decoder
                a_{t+1}
                  ↓ LM head
           下一 token x_{t+2} 的分布
```

### 7.2 目标：取消特征回归，直接优化 token 预测

EAGLE-1/2 既要求输出特征像目标模型，又要求 token 分布像目标模型。EAGLE-3 取消前者，允许内部向量 $a$ 采用更适合预测 token 的表示。

**“直接预测 token”不意味着没有内部向量或 LM head**。仍然是 decoder 产生向量，再经输出头得到 logits；变化是训练不再要求向量拟合目标模型真实 hidden state。

不能直接把 EAGLE-1 的 SmoothL1 加权公式照搬到 EAGLE-3。具体 token loss、词表映射和多步权重，应以所用训练实现为准。

### 7.3 方法：training-time test，训练时模拟多步递归

取消特征回归后，草稿输出 $a$ 不必接近目标模型融合特征 $g$。如果训练只用 $g$，后续推理改用 $a$，模型就可能不适应。

EAGLE-3 在训练中生成 $a$，再把它喂回草稿，训练后续步骤的 token 预测：

```text
第一步：目标模型融合特征 → 草稿向量 a₁ → token 预测监督
第二步：把 a₁ 喂回草稿   → 草稿向量 a₂ → token 预测监督
第三步：把 a₂ 喂回草稿   → 草稿向量 a₃ → token 预测监督
```

这是概念图，省略了 token embedding、历史 cache 和各位置的下标。训练还会调整 attention mask，保证各模拟分支只看自己的上下文；不能把不同位置的预测简单拼成一个普通句子。

training-time test 指训练期间模拟推理步骤，不是推理时再微调模型，也不意味着训练的所有细节都与实际采样生成完全相同。

三项改动的关系：

| 改动 | 作用 |
|---|---|
| 多层特征融合 | 提供更丰富的目标模型信息 |
| 取消特征回归 | 释放内部表示的约束，专注 token 预测 |
| 多步递归训练 | 适应自己的输出，改善后续步骤预测 |

来源：[EAGLE-3 论文 §3](https://arxiv.org/html/2503.01840v1#S3)。

## 8. 一轮完整推理如何执行

1. **Prefill 或上一轮验证**：目标模型处理已确定的上下文，获得真实特征和下一 token 分布。
2. **草稿生成**：结合已选 token 与真实特征开始预测，后续使用草稿自己的向量，构建候选树。
3. **并行验证**：目标模型用 tree attention 计算候选节点对应的真实概率。
4. **接受与修正**：沿候选路径执行相应验证算法，确定新增 token。
5. **更新状态**：保留有效 KV cache，用验证取得的真实特征开始下一轮。

EAGLE-1/2 从目标模型获取高层特征，EAGLE-3 获取多层融合特征。草稿内部向量并不会无限递归，轮间验证为后续草稿提供新的真实信息。

## 9. 为什么草稿猜错了也能保持输出分布

保证来自正确的验证和采样修正算法，而不是草稿必须足够准确。

以标准链式推测采样为例，设草稿分布为 $q$，目标模型分布为 $p$。对从 $q$ 采样出的候选 $x$，接受概率是：

$$
\alpha(x)=\min\left(1,\frac{p(x)}{q(x)}\right)
$$

拒绝时，从归一化的正差分布采样替代 token：

$$
r(v)\propto\max(0,p(v)-q(v))
$$

后续不再使用被拒绝路径的候选。树式验证需要相应的多候选处理，不能只把每个树节点独立套入上述公式就认为算法正确。

在正确的采样算法和概率处理下，最终输出分布与目标模型原本的解码分布一致。贪心解码通常按目标模型的选择验证前缀；随机采样时，分布一致不表示同一随机种子必然生成逐字相同文本。

来源：[EAGLE 论文](https://arxiv.org/abs/2401.15077)、[EAGLE-3 论文 §2.1](https://arxiv.org/html/2503.01840v1#S2.SS1)。

## 10. 训练和部署时关注哪些指标

| 指标 | 说明 |
|---|---|
| 训练 loss | 反映监督目标拟合程度，不直接等于加速收益 |
| 各预测深度的接受率 | 检查后续递归是否明显变差 |
| 每轮接受的草稿长度 | 衡量候选利用效果 |
| 每轮实际新增 token 数 | 包括验证阶段可能额外生成的 token；需确认统计口径 |
| 端到端延迟、tokens/s | 包括草稿、验证、输出头和缓存管理等开销 |
| 显存和并发吞吐 | 评估额外模型、候选节点和 cache 的成本 |

粗略成本模型：

$$
\text{平均每 token 耗时}\approx
\frac{T_{\mathrm{draft}}+T_{\mathrm{verify}}+T_{\mathrm{overhead}}}
{\text{每轮实际新增 token 数}}
$$

候选树越大、预测越深，额外计算也越多，不一定更快。效果取决于模型、硬件、任务、采样参数、上下文长度和并发。随着 batch 增大，目标模型可能更受计算能力限制，草稿额外计算的收益会变化，必须实测。

训练数据也应尽量匹配目标模型及部署任务。EAGLE-3 论文使用目标模型生成回答构造训练数据，并对推理模型增加相关数据；特定模型、模板和数据分布的变化都可能影响接受率。

来源：[EAGLE-3 论文实验与吞吐分析](https://arxiv.org/html/2503.01840v1#S4)。

## 11. 三个版本的对照

| 维度 | EAGLE-1 | EAGLE-2 | EAGLE-3 |
|---|---|---|---|
| 目标模型输入特征 | LM head 前的高层特征 | 延续 EAGLE-1 | 低、中、高层融合特征 |
| token 输入 | 比特征向前错开一个位置 | 同左 | 保留该对齐思路 |
| 草稿内部输出 | 受真实特征回归约束的预测特征 | 同左 | 无真实特征回归约束的内部向量 |
| 训练重点 | 特征回归 + token 分布拟合 | 核心草稿设计延续 EAGLE-1 | token 预测 + 多步递归训练 |
| 候选树 | 预定义结构 | 根据草稿置信度动态构建 | 延续动态树 |
| 主要改进 | 用特征与已选 token 做轻量预测 | 更有效地分配候选预算 | 更丰富输入、更自由表示、更好地适应递归 |
