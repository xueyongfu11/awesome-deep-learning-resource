# CUDA 线程层次、Warp 分歧与矩阵乘法优化

## 1. Thread、warp、CTA 与 SM

| 概念               | 含义                                                  |
| ------------------ | ----------------------------------------------------- |
| Thread             | 逻辑线程，有自己的数据和寄存器状态                    |
| Warp               | NVIDIA 上通常为 32 个线程，指令发射以 warp 为重要单位 |
| CTA / Thread Block | 多个 warp 组成的协作单元，共享内存并可进行 block 同步 |
| SM                 | 执行 CTA 的硬件单元，一个 CTA 不会拆到不同 SM 上执行  |
| Grid               | 某次 kernel 启动的全部 CTA                            |

一个 SM 能容纳多少 CTA 受寄存器、共享内存、线程和 block 上限等约束。任务数、实际驻留数量和计算吞吐是不同概念。

## 2. 为什么线程不能简单地各跑自己的分支

GPU 通过共享取指、译码和发射资源，降低每线程控制成本，并将更多资源用于计算。线程拥有独立逻辑状态，不等于各有独立执行硬件。

```cpp
if (threadIdx.x % 2 == 0) {
    A();
} else {
    B();
}
```

同一 warp 的线程选择不同路径时，产生分支分歧。可用下面的掩码执行模型理解：

| 指令路径 | 偶数线程 | 奇数线程 |
| -------- | -------- | -------- |
| A        | 参与     | 屏蔽     |
| B        | 屏蔽     | 参与     |
| 汇合后   | 继续     | 继续     |

被屏蔽的执行位置不会自动替换成另一分支的指令，因此有效并行度可能降低。短分支也可能被编译成谓词化指令。

Volta 及之后的独立线程调度增强了线程状态和调度的灵活性，但不意味着 32 个线程可以在一次 warp 指令发射中执行 32 条任意不同指令。不要依赖未经同步的隐式 warp 锁步假设。

不同 warp 选择不同路径通常不构成上述 warp 内分歧；整个 warp 一致进入一个分支也通常没有此类损失。

## 5. 常见优化

| 优化                | 方法                                   | 主要作用                       |
| ------------------- | -------------------------------------- | ------------------------------ |
| 合并访存            | warp 线程访问相邻地址                  | 减少无效事务                   |
| 共享内存分块        | block 协作加载 A/B tile，多次复用      | 降低重复全局访存               |
| 寄存器分块          | 每线程计算多个输出，累加器保存在寄存器 | 复用输入，减少共享内存访问     |
| 指令级并行          | 多个独立累加器，适度循环展开           | 隐藏计算依赖延迟               |
| 共享内存布局        | padding、swizzle、调整索引             | 降低 bank conflict             |
| 向量化访存          | 对齐条件允许时使用更宽加载/存储        | 减少指令数，不保证流量减少     |
| 双缓冲与流水        | 当前 tile 计算和后续 tile 加载重叠     | 隐藏加载延迟                   |
| tile 与线程布局调优 | 平衡复用、寄存器、共享内存和任务数     | 避免资源或并行度限制           |
| 形状特化与 split-K  | 针对小矩阵、细长矩阵选择算法           | 提高并行度；split-K 有归约成本 |
| 输出阶段融合        | 融合缩放、bias、激活                   | 减少 kernel 和中间读写         |
